# 新风格 20 种（sy-style-new20）

20 条 10 秒的纯画面短片（1920×1080、30fps、带程序合成的配乐音效，画面里没有文字和署名）。每一帧都是代码在无头浏览器里算出来的，`make.js` 一条命令出片。用户多半是**完全不懂编程的小白**，你替他把事情做完，再用一两句大白话告诉他结果。

## 1. 先找到包

包的位置：`{{PACKAGE_DIR}}`

- 安装程序会把上面这行换成真实路径。如果上面还是两对大括号包着的占位符（没换成路径），说明这份说明书是在包里直接读的：包的位置 = 这个 SKILL.md 往上两层、有 `make.js` 的那个文件夹。
- 下面所有命令都要**在包的文件夹里**运行：先 `cd` 进去，再 `node make.js ...`。
- 文件夹不存在（用户挪过或删了）：请用户告诉你包现在在哪；或者请他在新位置重新双击安装文件（`安装-Windows.bat` / `安装-Mac.command`），路径会自动更新。

## 2. 每次开工先检查

```
node make.js check
```

- 全是 √ 就直接干活。
- 有 × ：告诉用户缺什么，请他**双击包里的「安装-Windows.bat」**（Mac 是「安装-Mac.command」）重新装一遍，装完关掉终端 / 重开 AI 助手再继续。不要自己去改系统设置或全局配置。
- “显卡”一项是 · 不是 √：出图（still）没问题，但正式片要用软件渲染，一条半小时到一天多（见第 5 节）。这时 `style` 不会自己开始，会列出 3 个办法：下载 Releases 里的成片 / `--draft` 草稿 / `--cpu` 过夜跑。**这是少数要先问用户的情况**：用大白话把这 3 个办法和要等多久告诉他，让他选。

## 4. 出片

```
node make.js style 35          # 一条（也可以写 字符画、ascii）→ out/35-字符画.mp4
node make.js style 28 35 40    # 几条
node make.js style all         # 全部 20 条
node make.js still 35 5        # 只出一张图（第 5 秒）→ out/35-字符画_5s.jpg，几秒到一分钟
node make.js still 28 5 --compare  # 改过之后：原版和现在左右对比 → out/28-彩色玻璃窗_5s_对比.jpg
node make.js sheet 35          # 从成片抽 9 帧拼联系表 → out/35-字符画_联系表.jpg
node make.js status            # 看进行到哪了（也可以直接读 out/进度.txt）
node make.js list              # 列出 20 种
```

要点：

- **出片有显卡一条也要 4–13 分钟，一定放后台跑**，不要用默认的 2 分钟超时去等。Claude Code：Bash / PowerShell 工具加 `run_in_background: true`，跑完会通知你；其他 AI 助手用它们的后台 / 长任务方式，或者请用户自己在终端里运行这条命令。跑的过程中可以用 `node make.js status` 看进度。
- 开工前先说一句大概要多久（按第 3、5 节的耗时档）。
- 会自动：用显卡（显卡接口出问题会换一种再试；草稿和单张图可以退回软件渲染）、显示进度和剩余时间、配乐音效、把响度调到 -15 LUFS（真峰值 ≤ -1 dBTP）、做完删掉临时帧。
- **中断了**（关了窗口、电脑睡眠、报错）：再运行同一条命令，会从停下的地方接着做。
- 已经做好、画面又没改过的，会直接跳过（提示“已经做好了”）。要强制重做加 `--force`。
- **出完片先自己看一眼**：`node make.js sheet 编号` 出联系表（`out/编号-中文名_联系表.jpg`，9 帧），用读图工具看有没有黑屏、花屏、穿帮、颜色不对，没问题再告诉用户。
- 片子在包里的 `out` 文件夹，文件名 `编号-中文名.mp4`。做完告诉用户**完整路径**；用户想看就帮他打开文件夹（Windows：`explorer out`；Mac：`open out`）。
- 想快速看一下动起来的样子：`node make.js style 35 --draft`（半分辨率、不加运动模糊，快好几倍）→ `out/35-字符画_草稿.mp4`。

## 6. 常见报错怎么办

| 看到的提示 | 怎么办 |
|---|---|
| 还不能出片：渲染组件 / ffmpeg / Python 没装 | 请用户重新双击安装文件，装完重开终端或 AI 助手。刚装完找不到 ffmpeg / Python，多半也是没重开。 |
| 显卡渲染没成功，换一种显卡接口再试 | 不用管，它会自己换 d3d11、vulkan 接口重试。都不行时会停下并列出办法（同上：下载成片 / 草稿 / `--cpu`），转告用户让他选。 |
| 没检测到能用的显卡……（退出码 3） | 不是出错，是提醒：没显卡时正式片一条要半小时到一天多。把提示里的 3 个办法告诉用户，按他的选择运行。 |
| 画面全黑、花屏、颜色怪 | 多半是显卡驱动的问题。先 `node make.js still 编号 5 --cpu` 出一张软件渲染的图对比；再换显卡接口试：Windows 上 `set SY_ANGLE=vulkan` 或 `d3d11`（PowerShell：`$env:SY_ANGLE='vulkan'`）后加 `--force` 重出，默认是 `gl`。都不行才用 `--cpu --force`（很慢，见第 5 节）。 |
| 硬盘剩余空间不够 | `node make.js clean` 删临时帧；成片在 out 里不受影响。每条渲染时临时要几百 MB，做完自动删；出片前要求至少剩 2 GB。 |
| 没找到「xxx」这种风格 | 看 `node make.js list`，用编号最稳。 |
| 合成声音失败 | 多半是 numpy / scipy 没装好：重新双击安装文件。 |
| 加载失败 / 超时 | 软件渲染时第一次准备可能要几分钟，正常；显卡模式超时会自动换别的显卡接口重试。反复失败就把报错原文发给作者。 |
| 中文变成方块或字体不对 | fonts 文件夹缺文件：重新下载完整的包。 |

## 7. 用户要改颜色、光线、速度、内容

每个风格是 `styles/编号-名字/index.html`（一个网页，里面是画面代码：JS + 着色器字符串 GLSL）+ `music.py`（配乐和专属音效）+ `render.args`（渲染参数）。

### 改的流程（每次都这样）

1. **先备份**：把 `index.html` 复制一份叫 `index.原版.html`（已经有了就别覆盖，它是最初的原版）。
2. 查下面 7.2 的对照表，找到要改的地方，再读那一段代码确认。
3. 改代码。
4. 出对比图自查：`node make.js still 编号 1 5 9.5 --compare` → `out/编号-名字_5s_对比.jpg` 等（左原版、右修改后）。**自己用读图工具看一遍**：改对了没有、有没有黑屏、穿帮、颜色爆掉、光柱 / 光斑这些显眼的地方有没有一起变。
5. 把对比图给用户看，一句话说清改了什么。用户满意再 `node make.js style 编号` 出正式片（改过的会自动重做），做完照第 4 节看一眼联系表。
6. 用户说“换回原版”：把 `index.原版.html` 拷回 `index.html`。

### 7.1 改光色和改配色是两回事

- **改光色**（“偏蓝的晨光”“暖一点”“像傍晚”）：要找**光进入着色的地方**——灯的颜色乘到受光面上的那一步（常见写法：`alb * (光色 * 漫反射 + 环境光)`、`光色 * 高光`、光柱里 `acc += L * dust`），在那里乘光色。一束光往往不止一个入口：受光面、高光反射、光柱 / 雾、地上的光斑、溢光、反弹光，**要全部乘到**，不然最显眼的光柱、光斑不变。
- **改配色**（“玻璃换成绿色”“纸更黄”）：改物体本身的颜色（调色板、材质色）。改了配色，光的冷暖不会变。
- 已经做好“光色旋钮”的 8 个场景（26、28、29、30、31、34、38、40）：只改文件里的 `LIGHT_COL`（28 号叫 `SUN_COL`），默认 `vec3(1.)` = 和成片一模一样，乘上去的值就是光色的偏移。例如偏蓝晨光 `vec3(.78, .88, 1.15)`，更暖 `vec3(1.08, .95, .8)`，更暗整体乘一个小于 1 的数。别的光（天光、补光、灯笼等）对照表里写了在哪，要一起变就一起改。
- 其他场景：按对照表找到主光的那一个常量 / uniform（很多场景已经只有一处），或者照 7.1 第一条自己加一个 `const vec3 LIGHT_COL = vec3(1.);` 再乘到所有入口上；加完先用 `--compare` 确认**默认值时画面没变**，再改值。
- 着色器字符串里的注释只写英文（中文注释写在 JS 里），GLSL 里不要出现中文。
- 整片调色（不是改光，是后期滤镜）：用 `lib/rm.js` 的场景（24、25、28、29、31、35、37、40）可以在 `Reel.RM(stage, {...})` 参数里加 `gain: [r, g, b]`（例如偏冷 `[.95, .98, 1.05]`），最省事、零风险，但光和物体会一起被染色。

### 7.2 改颜色 / 改光线从哪下手（20 种对照表）

行号会随修改移动，按“搜什么”去找。★ = 已有光色旋钮。

| 风格 | 改光色（主光在哪进入着色） | 整体配色在哪 | 看着像、但别动 / 要同步 |
|---|---|---|---|
| 21 油画厚涂 | 主光就是一个 uniform：JS 里搜 `.f('Lc', 2.75, 2.3, 1.74)`（数值同时管颜色和亮度），所有受光面、高光、刮刀都用它；同一行 `.f('Ac', …)` 是冷色环境光。调色里 `vec3(.018,.006,-.016)` 把亮部推暖，要冷光时归零 | 背景笔触 `BG_D/BG_M/BG_L/BG_A`，桌、瓶、茎叶、花的色值在 JS 开头；画布底色 `vec3(.86,.84,.79)` | `LA`、`halo()` 是画里画出来的光（已画进笔触）；刀上颜料 `pa/pb` 要和笔触色同步；高度图 / 法线图的通道是数据 |

### 7.3 场景的规矩（一定要守）

- `render(t)` 必须是**确定性**的：同一个 t 永远画出同一张图。不能用 `Math.random()`、`Date.now()` 驱动画面，随机用 `Reel.rng(种子)` 或哈希。
- 时长 10 秒、30fps、1920×1080 不要改。节拍是 120 BPM（每拍 0.5 秒），动作落在拍点上。
- 改速度：运动由 `cam(t)` 和各种 `(t)` 函数控制。音效时间点写在 `Reel.scene({ cues: [{ t: 4.0, sfx: '名字', gain: 0.9 }] })`。**改了动作的快慢，就要同步改对应 cues 的 t**，不然声画对不上。出片时会自动从网页里重新导出 cues，不用手动跑别的。
- 音效 / 配乐：`music.py` 里的 `mus(...)` 每小节（2 秒）调用一次；`SFX_NEW = {名字: 函数}` 是这个风格专属的音效。乐器函数在 `audio/synth.py`。
- `render.args` 里的 `--mb N` 是运动模糊子帧数（每帧拍 N 张平均）。运镜改快了出现重影，就把 N 调大（最多 24，越大越慢）。
- 文字：这 20 条几乎没有画面文字。要加中文，用 `"Noto Sans CJK SC"`（字重只有 400 / 500 / 700），英文可用 `Inter`（500 / 600 / 700）、`DejaVu Sans Mono`、`TeX Gyre Heros Cn`。别的字体要先放进 `fonts/` 并在 `fonts/fonts.json` 登记（见 `fonts/LICENSES.md`）。

## 8. 和用户怎么说话

- 用户多半是小白：**简短、说人话、不甩术语、不贴日志**。
- 少提问：能自己判断就直接做，把假设说一句。比如“做出来”就是出正式片；“全部”就是 20 条；风格名对不上时列出最像的两三个让他挑。
- 开工时说：做哪几条、大概要多久、做完放哪。
- 完成时说：片子的完整路径、多长、用了多久；有失败的说清楚哪条、怎么办（通常是“再运行一次会接着做”）。
- 例：“字符画做好了：D:\sy-style-new20\out\35-字符画.mp4，10 秒高清带配乐，用了 5 分钟。要不要我顺手把 20 条都做了？”
